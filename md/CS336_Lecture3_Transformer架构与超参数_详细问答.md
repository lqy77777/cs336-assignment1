## 0. 一页总览：这节课到底在比较什么？

现代 decoder-only Transformer 的一层可以抽象成下面两条残差更新（省略 dropout、偏置等具体选择）：

```text
输入 x
  ├─ 归一化 → Q/K/V → 位置处理 → 注意力 → 输出投影 ─┐
  └────────────────── 残差相加 ←────────────────────┘
                         ↓
  ├─ 归一化 → FFN/门控激活 → 输出投影 ───────────────┐
  └────────────────── 残差相加 ←────────────────────┘
                         ↓
                       输出
```

课件的主线是：**哪些设计形成了广泛使用的默认配置，哪些仍是质量、稳定性与效率之间的取舍？**它不是一个“最新模型排行榜”；课件中出现的模型名只是设计例子。与 [Lecture 2 资源核算笔记](CS336_Lecture2_PyTorch与资源核算_面试问答.md) 的连接是：架构差异最终会改变参数量、FLOPs、激活/KV cache、数据搬运和实际吞吐。

本文统一使用以下符号：`B` 为 batch size，`T` 为序列长度，`L` 为层数，`d` 为 `d_model`，`f` 为 FFN 中间维度，`H_q` 为 query 头数，`H_kv` 为 key/value 头数，`d_h` 为每头维度，`V` 为词表大小，`s` 为每个元素的字节数。以下未特别说明时，讨论的是**稠密、因果、自回归**语言模型。

## 1. 基线结构与架构判断（PDF 第 1–9、27–29 页）

**Q1：原始 Transformer 与这门作业采用的简化现代结构有哪些主要差别？**  
A：课件把原始结构概括为 sinusoidal 位置编码、ReLU FFN、Post-LayerNorm；作业中的简化现代结构改用归一化位于子层前、RoPE、SwiGLU、以及大多不带 bias 的线性层。注意“现代”不是某个唯一标准，后面每个选择都有例外。

**Q2：为什么不能只记一个‘最佳 Transformer 架构’？**  
A：相同的参数预算也可以在训练稳定性、推理速度、长上下文能力和工程复杂度之间做不同取舍。课件第 5–7 页列举了很多近年的稠密模型，它们的共性很强，但仍在位置编码、门控、注意力模式和稳定性技巧上有差异。

**Q3：比较两个架构时，至少应控制什么？**  
A：要说清楚比较条件：参数量、训练 token/FLOPs、数据和 tokenizer、上下文长度、优化器与学习率、训练/推理硬件，以及最终指标。仅看“模型 A 指标高于模型 B”，不能证明某个单独模块更优。

**Q4：Transformer 层里的注意力和 FFN 分别负责什么？**  
A：注意力让一个 token 汇总其他位置的信息，建立跨 token 交互；FFN 对每个位置的向量做相同的非线性变换，主要增加逐 token 表达能力。FFN 本身不直接混合不同位置，但它接收的是已经过注意力更新的表示。

**Q5：什么是残差流（residual stream）？为什么本讲反复关注它？**  
A：残差流是层间持续传递的隐藏状态 `x`；子层结果加回这条主路径。其关键作用是保留一条相对直接的信息和梯度通路。归一化若直接放在每次残差相加之后，就会改变主路径的变换形式。

**Q6：Serial 与 Parallel block 的计算图有何区别？**  
A：串行结构先做 `a=x+Attn(N(x))`，再做 `y=a+FFN(N(a))`；并行结构可写为 `y=x+Attn(N(x))+FFN(N(x))`。并行两支看到的是同一个输入，可以共享归一化并更容易并行调度；串行 FFN 则能处理刚经过注意力更新的状态。是否更快、更好仍看实现和实验。

**Q7：为何课件提到并行层，结论却仍说多数模型采用串行层？**  
A：并行层有工程吸引力，课件列举了 GPT-J、PaLM、GPT-NeoX 等例子；但它不是无条件的质量或速度胜利。第 29 页是在总结课件观察到的模型分布，不是说并行层错误。

**Q8：如果面试官问‘选架构的原则’，最有用的回答框架是什么？**  
A：先提出约束：目标指标、训练计算预算、显存、推理延迟/吞吐、上下文长度；再选择成熟基线；最后通过受控消融比较一次只改一个因素。涉及系统性能时同时报告 FLOPs、内存/访存和 wall-clock，而不是只讲理论参数量。

## 2. Pre-Norm、Post-Norm、LayerNorm、RMSNorm（PDF 第 10–19 页）

先把四种常见写法放在一起；`F` 表示 attention 或 FFN 子层，`N` 表示归一化：

| 写法 | 单个残差子层的示意 | 对残差主路径的影响 |
| --- | --- | --- |
| Post-Norm | `y = N(x + F(x))` | 相加后仍要穿过 `N` |
| Pre-Norm | `y = x + F(N(x))` | 有显式恒等路径 `x → y` |
| 分支前后双 Norm / sandwich 式 | `y = x + N₂(F(N₁(x)))` | 两个 Norm 都在残差分支内，具体模型可能不同 |
| 最终 Norm | `output = N(x_L)` | 在所有层后处理最终表示，不等同于每层 Post-Norm |

**Q9：Pre-Norm 与 Post-Norm 的根本差别是什么？**  
A：差别是 Norm 相对**残差相加**的位置。Pre-Norm 在残差分支输入处归一化，输出为 `x+F(N(x))`；Post-Norm 在相加后归一化，输出为 `N(x+F(x))`。不能只看模块里有没有 LayerNorm，要按前向公式判断。

**Q10：为什么 Pre-Norm 往往更容易训练深层网络？**  
A：对 `y=x+F(N(x))` 求导，存在直接的恒等项 `∂y/∂x = I + ∂F(N(x))/∂x`；梯度有一条不必经过 `F` 和 Norm 的路径。Post-Norm 的梯度必须经过输出处的 Norm Jacobian，深层堆叠时更容易出现传播和初始化敏感问题。它是直觉，不代表 Pre-Norm 永远不会梯度爆炸或不需要 warmup。

**Q11：课件引用 Xiong 2020 来支持什么结论？**  
A：该工作分析了初始化时 Post-LN 与 Pre-LN 的梯度行为，说明 Norm 的位置会影响 warmup 的必要性。课件还展示了梯度尖峰与下游指标图（第 11–12 页）。这些证据支持“Pre-Norm 通常更稳定”，但来自特定实验和理论假设。参见 [Xiong 等人的原论文](https://arxiv.org/abs/2002.04745)。

**Q12：Pre-Norm 是否意味着可以无条件去掉学习率 warmup？**  
A：不意味着。Xiong 2020 的一个重要结果是某些 Pre-LN 设置可以不经 warmup 训练；现代大模型是否需要 warmup，还受到初始化、优化器、batch、并行策略和目标学习率影响。面试中把它说成“降低对 warmup 的依赖”更准确。

**Q13：为什么后来又出现‘双 Norm’或‘非残差路径 Post-Norm’？**  
A：设计者想让子层输入/输出更可控，同时保留残差主路径的恒等通路。其典型示意是 `x+N₂(F(N₁(x)))`：在分支里增加一次 Norm，而不是把整个 `x+F(...)` 的和送入 Norm。课件第 13 页列举 Gemma 2、OLMo 2 等变体；不要把所有“双 Norm”实现都写成完全相同的公式。

**Q14：LayerNorm 和 RMSNorm 的公式是什么？**  
A：对每个 token 的 `d` 维向量，LayerNorm 先减均值，再除以标准差：`LN(x)=γ⊙(x−μ)/√(σ²+ε)+β`；RMSNorm 通常写作 `RMS(x)=γ⊙x/√(mean(x²)+ε)`。`γ` 是逐维缩放，`β` 是偏置。RMSNorm 没有显式中心化，也通常没有 `β`。这里的均值在隐藏维上算，不跨 batch 或 token。

**Q15：RMSNorm 是否把输出变成均值为零、方差为一？**  
A：通常不会。它只根据均方根重缩放，**不减去均值**；均值非零时仍可能非零。不要把 RMSNorm 当成把 LayerNorm 公式中的 `β` 删掉而已。

**Q16：RMSNorm 为什么可能更快？‘少算几次’足以解释吗？**  
A：它少做中心化和部分归约，也少一个偏置参数；但在大模型里，矩阵乘法占绝大多数 FLOPs，所以单看 FLOPs 节省不一定大。归一化算子常受内存搬运、kernel 启动和融合方式影响，因此实际 wall-clock 收益需要测量。课件第 16 页正强调“FLOPs 不等于运行时间”。参见 [RMSNorm 原论文](https://arxiv.org/abs/1910.07467)。

**Q17：RMSNorm 一定比 LayerNorm 更好、更快吗？**  
A：不能保证。论文和课件展示了许多可比或更好的结果，但实际收益依赖任务、模型、算子融合与硬件。合适的说法是：它以更简化的归一化在不少 Transformer 配置中取得良好质量和效率，因此成为常见选择。

**Q18：为什么 Norm 中的 `ε` 很重要？放在根号内外一样吗？**  
A：`ε` 避免均方或方差过小导致除零，同时影响极小输入的缩放。`x/√(m+ε)` 与 `x/(√m+ε)` 并不完全等价，特别在 `m≈0` 时差异明显；实现时应与论文/作业定义保持一致。

**Q19：`γ`、`β` 与线性层 bias 分别是什么？**  
A：`γ`、`β` 是归一化后的逐维仿射参数；线性层 bias 是 `xW+b` 中的加性参数。课件讨论“去 bias”时既涉及线性投影，也涉及 RMSNorm 不使用 LayerNorm 式 `β`；不能因为都叫 bias 就混成一个参数。

**Q20：为什么一些模型删除线性层 bias？**  
A：这可减少参数和额外的加法/访存，并可能改变优化行为；但相对于 `d×f` 的权重矩阵，单个长度 `f` 的 bias 参数很少。是否显著提速要看 kernel 是否融合，不能把“少参数”直接等同于“明显更快”。

**Q21：如果训练深层模型出现 loss spike，应先把所有 Norm 改成 RMSNorm 吗？**  
A：不应直接归因。先查学习率、warmup、梯度范数、初始化、精度溢出，以及 attention/output logits；再用受控实验比较 Norm 类型或位置。LayerNorm 与 RMSNorm 是“怎么算归一化”，Pre/Post-Norm 是“归一化放哪里”，两条轴应分开排查。

## 3. FFN、激活函数、门控与串并行（PDF 第 20–29 页）

令输入最后一维为 `d`，中间维为 `f`；忽略 bias 后：

```text
普通 FFN：     h = φ(xW_up)                 y = hW_down
门控 FFN：     h = φ(xW_gate) ⊙ (xW_up)  y = hW_down
W_gate、W_up: d×f；W_down: f×d；⊙ 是逐元素乘法。
```

| 激活/门控 | `φ(z)` 或核心形式 | 直观性质 |
| --- | --- | --- |
| ReLU | `max(0,z)` | 简单，负半轴硬截断 |
| GELU | `z Φ(z)`，`Φ` 是标准正态 CDF | 平滑门控；实现常用近似 |
| Swish/SiLU | `z sigmoid(z)` | 平滑、非单调区间 |
| ReGLU | `ReLU(xW_gate) ⊙ xW_up` | 多一条可学习投影 |
| GeGLU | `GELU(xW_gate) ⊙ xW_up` | GELU 门控 |
| SwiGLU | `Swish(xW_gate) ⊙ xW_up` | Swish 门控 |

**Q22：FFN 为什么需要非线性激活？**  
A：两个纯线性层复合仍等价于一个线性变换，不能增加非线性表达能力。激活函数或门控乘法引入非线性，使逐 token 表示能更复杂地变化。

**Q23：GLU 类 FFN 的‘gate’到底在控制什么？**  
A：一条投影经过非线性函数后，逐元素调制另一条投影的输出。它不是只在最后做一次标量开关，而是每个 token 的每个中间特征都有自己的调制值；因此两个输入依赖的分支可以发生乘性交互。

**Q24：SwiGLU 与 Swish 是同一个东西吗？**  
A：不是。Swish/SiLU 是单变量激活 `z sigmoid(z)`；SwiGLU 是 `Swish(xW_gate) ⊙ (xW_up)` 再投影回 `d` 的门控 FFN，包含额外的矩阵权重。

**Q25：为什么使用门控后，常把 `d_ff` 从 `4d` 缩到 `8d/3`？**  
A：普通 FFN 两个矩阵约有 `2df` 个参数，若 `f=4d` 则为 `8d²`；门控 FFN 有三个矩阵约 `3df_g`，取 `f_g=8d/3` 也得到 `8d²`。这是在**大致相同参数和主导矩阵乘 FLOPs 预算**下比较质量，而不是说门控天然更省参数。逐元素门控仍有额外开销。

**Q26：如果保持 `f=4d` 不变，只把 ReLU FFN 换成 SwiGLU，会怎样？**  
A：FFN 主矩阵从 2 个变 3 个，主导参数/FLOPs 从约 `8d²` 增为 `12d²`，涨了 50%。若指标变好，就无法区分收益来自门控机制还是更多参数/计算，因而做消融时要注意预算匹配。

**Q27：门控 FFN 的激活张量形状如何检查？**  
A：若 `x:[B,T,d]`，则 `xW_gate` 与 `xW_up` 都应是 `[B,T,f_g]`，才能逐元素相乘；`W_down:[f_g,d]` 把结果变回 `[B,T,d]` 供残差相加。任何中间维度不一致都会在乘法或残差处出错。

**Q28：讲义是否证明了 SwiGLU 必然优于 GELU/ReLU？**  
A：没有。第 24–25 页引用 Shazeer 2020 与 Narang 2020 的实验，显示一些门控变体在相近预算下较常带来收益；结果仍受任务、训练设置和评价指标影响。它是强经验默认项，而非数学最优定理。参见 [GLU Variants Improve Transformer](https://arxiv.org/abs/2002.05202)。

**Q29：为什么 PaLM 等模型会把 attention 和 FFN 并行？**  
A：两支可以读取同一个归一化输入，同时计算并合并结果，从而减少层内串行依赖；某些实现还能共享 Norm 或融合矩阵乘。收益依赖硬件调度、通信和训练质量，不能只靠画出的并行图保证提速。

**Q30：并行 block 的两个分支相加时，需要什么形状条件？**  
A：`Attn(N(x))`、`FFN(N(x))` 和 `x` 的输出都必须是 `[B,T,d]`。内部注意力和 FFN 可以用不同中间维度，但最终投影必须回到模型维度 `d`。

**Q31：注意力和 FFN 的先后顺序会改变函数类吗？**  
A：会影响可表达的计算路径。串行 FFN 看得到同层 attention 汇总后的结果；并行 FFN 只看本层原输入，两个分支在相加处汇合。不过多层堆叠仍可跨层交互，单层差异不直接决定最终质量。

**Q32：为什么‘矩阵乘法 FLOPs 几乎没变’不等于两个 FFN 实现耗时相同？**  
A：中间激活大小、逐元素门控、临时张量写回、融合程度以及矩阵形状都会影响访存和 Tensor Core 利用率。面试时应把“参数/FLOPs 匹配”和“实测 wall-clock 匹配”分开。

**Q33：没有 bias 的 FFN 是否就不能表示非零常数？**  
A：单独一个无 bias 线性变换对零输入输出为零，但整层还包含残差、归一化缩放、非线性和其他上下文；不能据此断言整个模型无法产生非零或复杂输出。真正的问题是去 bias 在给定架构与训练条件下的表达/效率取舍。

**Q34：面试中怎样在 30 秒内比较 ReLU、GELU 和 SwiGLU？**  
A：ReLU 是简单硬截断；GELU 是平滑的单分支激活；SwiGLU 用两条线性分支做逐元素门控，通常在匹配预算下缩小中间维度到约 `8d/3`。课件的经验是门控变体常有收益，但要同时比较质量、FLOPs 与实际吞吐。

## 4. 位置编码与 RoPE（PDF 第 30–35 页）

先区分位置进入模型的方式：固定正弦或可学习绝对位置向量通常**加到 token 表示上**；某些相对位置方法直接改变 attention score/bias；RoPE 则对**每层的 Q 和 K**按位置做二维旋转。它们不是同一种“embedding 表”。

对二维一组坐标，令 `R(α)=[[cos α,−sin α],[sin α,cos α]]`。位置 `i` 的 query 与位置 `j` 的 key 分别旋转后：

\[
q_i=R(i\theta)q,\quad k_j=R(j\theta)k,\qquad
q_i^\top k_j=q^\top R((j-i)\theta)k.
\]

关键一步是 `R(iθ)ᵀR(jθ)=R((j−i)θ)`。在多维 RoPE 中，把偶数维向量分成多对坐标，每对使用不同频率；注意力分数因此自然包含相对位置差。参见 [RoFormer 原论文](https://arxiv.org/abs/2104.09864)。

**Q35：为什么纯 token embedding 无法让无位置的 self-attention 识别顺序？**  
A：没有位置信号时，注意力只能根据内容向量计算相似度；对输入位置做共同置换，输出也相应置换，模型没有内生的“第几个 token”概念。因果 mask 告诉模型哪些位置可见，但并不能提供所有相对距离信息。

**Q36：固定正弦与可学习绝对位置编码有什么共同点？**  
A：两者都可把位置向量加到 token 表示上，随后一起进入 Q/K/V 投影；区别是固定正弦由公式生成，可学习绝对向量由训练得到。两者都可能通过后续网络利用位置信息，但相同内容在不同绝对位置输入不同。

**Q37：为何说‘正弦位置编码不是严格相对位置’时要加限定？**  
A：纯位置向量之间的某些内积确实可写成位置差函数；但当位置向量**加到内容向量**后，attention 点积会出现内容–位置交叉项，通常不能只由 `i−j` 决定。课件第 31 页批评的是这个加法后完整注意力分数，不是说正弦函数与相对位移毫无关系。

**Q38：RoPE 为什么只旋转 Q/K，通常不旋转 V？**  
A：RoPE 想让决定“看谁”的相似度 `q_i·k_j` 显式编码相对位置；V 是被加权汇总的内容。旋转 V 会改变汇总值本身，不是该标准机制实现相对位置分数所必需的。具体变体可能另有设计。

**Q39：RoPE 的二维旋转公式如何手写？**  
A：对一对坐标 `(a,b)`，位置 `m`、频率 `θ` 下得到 `(a cos(mθ)−b sin(mθ), a sin(mθ)+b cos(mθ))`。检验方法是旋转前后平方范数不变：`a'²+b'²=a²+b²`。

**Q40：怎样用一个小例子验证 RoPE 的相对位置性质？**  
A：设 `q=k=(1,0)`，某一对坐标的 `θ=π/3`。位置 `(i,j)=(1,2)` 的点积为 `cos(π/3)=1/2`；一起平移到 `(3,4)`，点积仍为 `1/2`，因为位置差都为 1。

**Q41：RoPE 中位置 `m` 对不同维度使用同一个旋转角吗？**  
A：通常不是。每对坐标有自己的频率 `θ_r`，位置角为 `mθ_r`；不同频率让不同维度对距离有不同尺度的响应。具体频率基数、分组方式和只旋转部分维度等都属于实现/超参数选择。

**Q42：RoPE 的‘相对位置性质’是否意味着模型完全不知道绝对位置？**  
A：不能这么说。单个理想化 Q/K 内积对共同平移具有相对位移结构，但因果边界、序列开头/结尾、其他输入特征、频率设置和网络整体计算仍可能让模型形成位置相关行为。这里讨论的是 attention score 的一项代数性质。

**Q43：RoPE 应放在 Q/K 投影之前还是之后？**  
A：标准思路是先将隐藏状态投影并整理成各头的 Q/K，再按位置对每头向量的成对坐标旋转，最后计算 `QKᵀ/√d_h`。课件第 35 页的代码示意也是在 Q/K 投影后调用 `apply_rotary_pos_emb`。不同实现的 QK-Norm 与 RoPE 相对顺序需看模型定义。

**Q44：KV cache 与 RoPE 同用时最容易写错什么？**  
A：增量解码时新 query/key 必须使用**全局 token 位置**，而不是每次都把新 token 当作位置 0。已缓存 key 的旋转位置也必须与它实际生成时的位置一致；否则相对位置差错误，生成结果可能明显变差。

**Q45：RoPE 可以无代价外推到任意长上下文吗？**  
A：不能。公式可计算更大的位置索引，但训练中未见过的相位组合、频率混叠与注意力分布变化可能损害质量。长上下文扩展常需要频率缩放、插值或重新训练/适配，并应以目标长度评估。

**Q46：RoPE 与‘直接给 attention score 加相对位置 bias’有何区别？**  
A：RoPE 改变 Q/K 的几何表示，使点积自身携带相对位移；相对 bias 是在原始内容分数之外，按距离另加一项。二者对 score 的作用形式不同，参数化和推理实现也不同。

**Q47：面试官给你 `q:[B,H,T,d_h]`，如何检查 RoPE 实现的维度？**  
A：最常见实现要求被旋转的维数为偶数，正余弦表与 `[T,d_rot/2]` 或可广播的等价形状对齐；旋转后仍保持 `[B,H,T,d_h]`。还要检查 dtype/device、位置 offset，以及 Q 和 K 对应的绝对位置是否一致。

**Q48：为什么旋转能避免‘内容 + 位置’加法中的交叉项？**  
A：RoPE 把位置编码放进对 Q/K 的线性正交变换。点积可合并成 `qᵀR((j−i)θ)k`，只出现相对旋转，而不会展开出 `q·p_j`、`p_i·k` 这类加法交叉项。这是该设计的主要数学动机。

**Q49：如果所有位置都加同一个偏移量 `c`，RoPE 注意力分数会怎样？**  
A：在上述理想旋转公式中，`R((i+c)θ)ᵀR((j+c)θ)=R((j−i)θ)`，所以同一对内容向量的点积分数不变。面试时应明确“同一对内容向量、相同频率和位置处理”的前提。

## 5. 宽度、深度、头数、词表等超参数（PDF 第 36–47、51 页）

一个有用的参数账本（**推导/延伸**）：若是普通 MHA，`H_q d_h=d`，Q/K/V/O 四个主要投影约 `4d²` 参数；普通 FFN 为 `2df`，SwiGLU 为 `3df`。所以 `f=4d` 的普通 FFN 或 `f=8d/3` 的 SwiGLU 都约占 `8d²`，整层主矩阵约 `12d²`，总量近似 `P≈12Ld²+Vd`（输入/输出 embedding 共享时）。这忽略 Norm、bias、特殊头、GQA、未绑定的输出层等，适合快速估算，不适合替代模型配置文件。

**Q50：课件对普通 FFN 的 `d_ff/d_model` 给了什么经验值？**  
A：常见起点是 `f≈4d`。课件第 37、41 页强调许多模型聚集在这个数量级，但并非必须；要看是否门控、参数预算和目标系统效率。

**Q51：为什么 SwiGLU 的常见比例约为 `8/3`，并不意味着它‘更窄所以更弱’？**  
A：它多出一条矩阵投影，`3d(8d/3)=8d²` 与普通 `2d(4d)=8d²` 接近。比较的是总参数/主要计算预算，而不是孤立地比较中间层的宽度。

**Q52：`d_ff=4d` 是理论最优值吗？**  
A：不是。课件第 40 页引用的实验曲线在较宽的比例区间形成性能较平坦的“盆地”；这说明对该实验，比例不是必须精调到某个单点。不同模型规模、门控方式和训练预算可能改变最佳值。

**Q53：课件用 T5 的极端 FFN 比例说明什么？**  
A：其列出的 T5 11B 配置有 `d=1024`、`f=65536`，比值达到 64，说明非常规比例也能训练并产出可用模型；这不证明 64 更好。课件同时指出后续 T5 v1.1 回到更常见的门控比例，因此不能拿单一例子当推荐默认值。

**Q54：如何从架构表估算一层的主参数量？**  
A：普通 MHA 的 Q/K/V/O 约 `4d²`；普通 FFN 约 `2df`，门控 FFN 约 `3df`。例如 `d=2048`、普通 `f=8192` 时，注意力约 `4×2048²`，FFN 约 `2×2048×8192`，合计约 `12×2048²≈50.3M` 个主矩阵参数/层。

**Q55：为什么 `H_q × d_h = d_model` 是常见设置，却不是数学定律？**  
A：这是把 Q 的总投影宽度设为 `d` 的方便设计，便于 reshape 和参数预算；完全可以投影到 `H_q d_h ≠ d`，再由输出投影映回 `d`。点积只要求每一对 query/key 头的点积维度匹配，不要求所有头拼接后的宽度必须等于输入宽度。

**Q56：头数增加一定会提高多头注意力的主导 FLOPs 吗？**  
A：若保持 `H_q d_h=d` 不变，则 `QKᵀ` 和 `AV` 的主项分别约与 `B T² H_q d_h = B T² d` 成正比；并不会仅因头数变多就线性增加主导 FLOPs。实际性能仍可能因每头更窄、kernel 形状、并行度和 softmax 开销变化。

**Q57：如果 `H_q d_h` 大于 `d`，参数和计算会怎样？**  
A：Q/K/V 等投影输出更宽，相关矩阵参数与 attention 乘法成本通常增加；模型可能获得不同表达能力，也可能只是浪费预算。必须按具体的 Q、K、V 维度分别核算，不能继续套用 `4d²` 或 `BT²d`。

**Q58：课件第 43 页 PaLM 行有什么算术问题？面试时怎么处理？**  
A：表里写 `48` 头、`head dim=258`、`d=18432`、ratio `1.48`，但 `48×258/18432≈0.672`，与 ratio 不符。[PaLM 原论文](https://arxiv.org/abs/2204.02311)给出的 head size 是 `256`；按这三个数算 `48×256/18432=2/3`，仍不是 `1.48`。因此这行疑似有笔误或比值方向混淆，应直接列公式重算，不要背表中数值。

**Q59：`d_model / n_layers`（课件称 aspect ratio）是什么？**  
A：它是一个**宽度/深度的经验性指标**，分子与分母单位并不相同，所以只是比较模型形状的简写。课件第 44 页举出不少模型约在 100–200 的范围，也有明显例外；它不是架构必须满足的物理约束。

**Q60：固定参数预算时，为什么‘更深’和‘更宽’会有系统层面的差别？**  
A：在近似 `P≈12Ld²` 下，增加层数就必须降低宽度才能保持预算。更深会增加顺序依赖与推理延迟，跨流水线并行也更复杂；更宽会增大单层矩阵和激活，可能改善大矩阵计算利用率，但也可能增加设备内存压力。质量取舍需实验验证。

**Q61：课件第 46 页的深宽比曲线支持什么，不支持什么？**  
A：它显示多个固定参数规模的实验在相当一段 aspect ratio 范围内性能相近，且极端配置会变差。它不支持“所有任务和硬件都应取 128”；系统延迟、并行方式和上下文长度可改变实际最佳点。

**Q62：词表大小 `V` 为什么会改变模型参数量？**  
A：输入 token embedding 通常约 `Vd` 参数；若输出分类权重不与输入 embedding 共享，还可能再有约 `Vd`。词表越大，embedding 和输出 logits/softmax 的成本越高，但可能减少一段文本的 token 数。

**Q63：为什么多语言模型往往采用更大的词表？**  
A：覆盖更多语言、文字系统和常见片段，能减少一些语言被切成很多短 token 的现象；但更大词表也提高 embedding 与输出层成本。课件第 47 页列出“单语常见 3–5 万、多语言/生产系统常见 10–25 万”作为当时模型的观察，不能当作所有语言/语料的最优范围。

**Q64：词表变大是否一定使训练和推理更快？**  
A：不一定。每段文本可能需要更少 token，但每个 token 的输出投影和 softmax 面对更大的 `V`，embedding 参数也增加。要比较的是相同原始文本上的总 token 数、有效上下文覆盖、模型质量与端到端吞吐。

**Q65：若一个模型 `L=24`、`d=2048`、`V=50000`，参数量怎么粗估？**  
A：用上面的简化账本，层参数约 `12×24×2048²≈1.208B`；一个共享 embedding 约 `50000×2048≈0.102B`；合计约 `1.31B`。不共享输出权重时再加约 `0.102B`，GQA、bias、Norm 等也会改变数值。

**Q66：除了 `V`，tokenizer 会怎样间接影响架构选择？**  
A：同样文本被切成多少 token 会影响上下文长度需求、attention 计算和训练 token 预算。比较模型时不能只报 `V`，还应观察目标语言与领域的 token/字符比例、特殊 token 设计和实际覆盖情况。

**Q67：选择超参数时，为什么先用常见配置再调一个轴更稳妥？**  
A：这些经验值提供了已知可工作的起点；若同时改 FFN 比例、头维、Norm、tokenizer 和训练计划，指标变化无法归因。面试中应提出固定预算的消融：明确质量、吞吐、显存和稳定性四类观测。

## 6. Dropout 与 Weight Decay（PDF 第 48–51 页）

课件的实证观察是：不少早期模型预训练用 dropout；表中一些较新的开放模型将 dropout 设为 0，但仍保留 weight decay。模型论文未讨论某项设置，不等于我们能确信其闭源实现为 0。

**Q68：Dropout 和 weight decay 作用在同一个地方吗？**  
A：不是。Dropout 训练时随机屏蔽部分激活/连接路径，改变每步的有效计算图；weight decay 在参数更新时倾向于缩小权重。两者都可影响泛化，但实施位置和对优化动态的影响不同。

**Q69：为什么海量语料预训练有时不需要 dropout？**  
A：若训练数据非常多、重复次数少，传统意义上的训练集记忆可能较弱；Dropout 的噪声与额外算子也未必划算。这是背景解释，不是“LLM 一定不需正则化”的定理；小数据微调更不能照搬。

**Q70：课件是否认为 weight decay 仅仅用于防止过拟合？**  
A：不是。第 50 页引用的研究强调在近单遍预训练中，weight decay 还能通过改变优化动态影响训练损失与稳定性；不能只用“训练/验证 gap 是否变大”评价它。参见 [D'Angelo、Andriushchenko 等人的原论文](https://arxiv.org/abs/2310.04415)。

**Q71：AdamW 的 decoupled weight decay 更新如何口述？**  
A：可写成 `w_{t+1}=(1−η_t λ)w_t−η_t·AdamUpdate_t`，其中 `η_t` 是当前学习率，`λ` 是衰减系数。衰减直接作用在权重上，与把 `λw` 加到梯度再送入 Adam 自适应缩放不同；这也是名称中 “W” 的重要含义。

**Q72：为什么 weight decay 会与学习率 schedule 相互作用？**  
A：每步乘上的收缩因子是 `1−η_t λ`，跨训练过程的总效应近似与 `Σ_t η_t λ` 有关。学习率在余弦退火中逐渐变小，同样的 `λ` 在不同阶段产生不同强度的实际收缩，所以不能孤立地谈衰减系数。

**Q73：若一个模型 dropout 为 0、weight decay 非 0，能否说它没有正则化？**  
A：不能。它仍有显式的权重衰减，且数据、随机梯度、早停和模型结构本身也影响泛化。课件“较新模型只靠 weight decay”只是表中案例的归纳。

**Q74：在实验中如何判断 weight decay 在帮忙？**  
A：固定其他条件，对不同 `λ` 记录训练 loss、验证 loss、梯度/权重范数、loss spike 与最终任务指标；同时记录学习率计划。如果训练 loss 与验证 loss 都改善，说明它可能改变了优化过程，而非仅减少过拟合。

## 7. 训练稳定性：softmax、z-loss、QK-Norm、soft-capping（PDF 第 52–56 页）

这里有**两个不同的 softmax**：注意力 softmax 作用于一个 query 对各 key 的分数；输出 softmax 作用于下一个 token 的词表 logits。课件讨论的稳定性技巧分别放在它们的输入处，不能混为一谈。

设输出层的词表 logits 为 `z∈R^V`，目标 token 为 `y`：

\[
\operatorname{CE}(z,y)=-z_y+\log\sum_{v=1}^{V}e^{z_v},\qquad
\operatorname{zloss}(z)=\alpha\left(\log\sum_{v=1}^{V}e^{z_v}\right)^2.
\]

在**最小化**训练损失的口径下，`total_loss = CE + zloss`。课件第 54 页引用的图使用对数似然/最大化目标的记法，符号与上式看似相反；复述时应先说清楚优化方向。PaLM 报告过使用 `α=10⁻⁴`，它是该模型的一项配置，不是通用常数。参见 [PaLM 原论文](https://arxiv.org/abs/2204.02311)。

**Q75：为什么 softmax 输入过大可能导致训练问题？**  
A：朴素 `exp(z)` 可能溢出，注意力分数差距过大还会让 softmax 极端尖锐、某些梯度很小。实现通常用稳定的 `logsumexp`/减最大值处理数值溢出；但若 logits 整体尺度持续漂移，仅靠稳定实现并不约束模型行为。

**Q76：稳定 softmax 的‘减最大值’怎样推导？**  
A：令 `m=max_i z_i`，则 `softmax(z)_i=exp(z_i−m)/Σ_j exp(z_j−m)`；分子分母同时乘 `exp(−m)`，概率不变。减完后最大指数为 `exp(0)=1`，避免大正数直接进入指数函数。

**Q77：z-loss 想解决的是什么？**  
A：普通交叉熵对所有 logits 共同加常数不变，`softmax(z+c·1)=softmax(z)`；模型在这个共同平移方向上没有来自 CE 的直接约束。z-loss 惩罚 `logZ=logsumexp(z)` 偏离 0，抑制该方向的漂移和过大的归一化常数。

**Q78：可以用两个 logits 的小例子说明 z-loss 吗？**  
A：`z=[1,0]` 与 `z'=[11,10]` 给出完全相同的 softmax 概率；但 `logsumexp(z')=logsumexp(z)+10`，z-loss 会更强烈惩罚后者。注意 z-loss 不是把最大 logit 硬截断到 0。

**Q79：z-loss 与 `logsumexp` 的稳定实现是同一件事吗？**  
A：不是。稳定实现是**数值计算方法**，在数学上不改变原目标；z-loss 是**额外的训练目标项**，会改变梯度和模型学到的参数。两者可以同时使用。

**Q80：QK-Norm 放在 attention 的哪里？**  
A：Q/K 经各自线性投影后，在计算点积分数前对每头 query 与 key 做归一化，随后计算类似 `softmax(q̂k̂ᵀ/√d_h)` 的注意力。具体用 LayerNorm 或 RMSNorm、是否带缩放参数、与 RoPE 的先后顺序要看模型实现。

**Q81：Pre-Norm 已经归一化了 `x`，为什么还可能要 QK-Norm？**  
A：Pre-Norm 控制子层输入 `x` 的尺度；Q/K 投影矩阵可在训练中增大输出范数，使点积 logits 仍变大。QK-Norm 直接作用在 softmax 前的 Q/K，针对的是更靠近问题源头的量。两者作用位置不同。

**Q82：QK-Norm 对注意力分数的尺度有什么直觉影响？**  
A：若 Q/K 的每头范数被控制，点积不再随投影向量范数任意放大，softmax 温度更容易保持在可训练范围。它不能保证任何设置都不会出现尖峰，也可能改变注意力的表达方式。

**Q83：什么是 logit soft-capping？**  
A：把某个分数 `z` 映为 `f(z)=c·tanh(z/c)`，输出限制在 `(-c,c)`。Gemma 2 报告在注意力分数和最终输出 logits 上使用不同的 `c`；课件第 56 页引用了该实例。参见 [Gemma 2 技术报告](https://arxiv.org/abs/2408.00118)。

**Q84：soft-capping 与硬 `clamp(z,−c,c)` 有什么不同？**  
A：soft-capping 是平滑函数，`z` 接近 0 时近似恒等映射；大幅度时逐渐饱和。其导数为 `sech²(z/c)`，大 `|z|` 时很小；硬截断在边界不可导，并在截断区通常给零梯度。

**Q85：soft-capping 会不会永远提升质量和稳定性？**  
A：不会。它可以限制极端 logits，却也可能让很大的分数进入梯度饱和区，或与高效 fused attention kernel 的实现发生冲突。课件第 56 页就提醒了可能的性能问题，应按模型和任务消融。

**Q86：QK-Norm 与 soft-capping 在作用机理上如何比较？**  
A：QK-Norm 约束形成 logits 的 Q/K 向量尺度；soft-capping 在 logits 形成后直接做非线性压缩。前者改变相似度几何，后者改变分数映射；也可以组合，但组合收益不是简单相加。

**Q87：z-loss 与注意力 QK-Norm 会互相替代吗？**  
A：不会。z-loss 作用在**词表输出分布**的 `logZ`；QK-Norm 作用在**注意力分布**的 Q/K。两个 softmax 的维度、功能和风险不同，定位 loss spike 时应分别检查。

**Q88：如果训练出现 NaN，怎样有条理地排查？**  
A：先定位第一次出现非有限值的张量或步骤：loss、输出 logits、QK scores、梯度、优化器状态；再查 dtype/AMP、学习率、梯度范数、Norm `ε`、稳定 softmax 实现和异常数据。确认是哪个分布或算子先出问题后，再评估 z-loss、QK-Norm、soft-capping 等改动。

## 8. MHA、MQA、GQA、KV cache 与解码成本（PDF 第 57–63 页）

先记住三者的核心区别是 **KV 头数**，不是 query 头数：

| 机制 | Query 头数 | KV 头数 | 每个 KV 头服务多少 Q 头 |
| --- | ---: | ---: | ---: |
| MHA | `H_q` | `H_kv=H_q` | 1 |
| GQA | `H_q` | `1<H_kv<H_q` | 通常 `H_q/H_kv` |
| MQA | `H_q` | `H_kv=1` | `H_q` |

假设每个 K/V 头宽 `d_h`，缓存 `L` 层、`B` 条序列、每条已生成/可见 `T` 个 token，KV cache 的**原始张量数据量**约为：

\[
M_{KV}=2\,LBT H_{kv} d_h s.
\]

前面的 `2` 分别对应 K 和 V。它尚未包括分配器碎片、页表/索引、批间长度差异和临时缓冲。固定其他变量，从 MHA 改成 GQA 后，**KV 数据本体**按 `H_kv/H_q` 比例缩小。

**Q89：完整 MHA 的基本张量形状是什么？**  
A：输入 `X:[B,T,d]`，常见 Q/K/V reshape 为 `[B,H_q,T,d_h]`（MHA 时头数相同）；分数为 `[B,H_q,T,T]`，乘 V 后各头结果为 `[B,H_q,T,d_h]`，最后合并并投影回 `[B,T,d]`。因果 mask 限制只能看到当前位置及以前。

**Q90：Prefill 与 Decode 对 attention 的计算形状有何差别？**  
A：prefill 一次处理已有 prompt 的很多位置，能做较大的矩阵乘；decode 每一步只生成一个新 token，新 query 读历史 K/V，与长度 `T` 的缓存交互。decode 的步骤间依赖使 token 不能沿时间轴完全并行。

**Q91：KV cache 缓存的是什么，为什么能加速增量生成？**  
A：每层历史 token 的 K 和 V。生成新 token 时只需计算新位置的 Q/K/V，把新的 K/V 追加进去，再让新 Q 与已有 K/V 做注意力；不用为所有历史 token 重算整个网络的 K/V。

**Q92：KV cache 为什么又会成为瓶颈？**  
A：上下文越长，每一步需要读取的历史 K/V 越多，缓存容量和 HBM 访存随 `B×T×L×H_kv×d_h` 增长。低 batch decode 中，权重读取和 KV 读取都可能限制吞吐。

**Q93：如何手算一份 KV cache 的大小？**  
A：取 `L=32`、`B=1`、`T=4096`、`H_q=32`、`d_h=128`、bf16 为 `s=2`。MHA `H_kv=32` 时约 `2 GiB`；GQA `H_kv=8` 时约 `512 MiB`；MQA `H_kv=1` 时约 `64 MiB`。这是原始数据量，非运行时显存峰值。

**Q94：MQA 究竟共享了什么？**  
A：保留多个 Q 头，但让它们使用同一组 K/V 头；每个 Q 头依然有自己的 query 和对应的 attention 权重。课件第 61 页写的“one dimension for keys and values”应理解为**一组 KV 头**，不是把每个 key/value 向量压缩为标量。参见 [Shazeer 的 MQA 原论文](https://arxiv.org/abs/1911.02150)。

**Q95：GQA 是怎样介于 MHA 与 MQA 之间的？**  
A：把 Q 头分组，同组的几个 Q 头共享一组 K/V。例：`H_q=32`、`H_kv=8`，每 4 个 Q 头用同一 KV 头；缓存比 MHA 缩到约 1/4，但每个 query 仍有独立注意力分数。参见 [Ainslie 等人的 GQA 原论文](https://arxiv.org/abs/2305.13245)。

**Q96：`H_q` 一定要能被 `H_kv` 整除吗？**  
A：常见的**均匀分组实现**要求能整除，这样每组大小为 `H_q/H_kv`，广播/重复 K/V 很方便。数学上可以设计不均匀共享关系，但不是通常说的标准 GQA 配置。

**Q97：从 MHA 到 GQA，哪些成本近似按 `H_kv` 下降？**  
A：K/V 投影的输出维度与参数、KV cache 容量、decode 读取历史 KV 的字节量，通常会随 `H_kv` 下降。具体速度还取决于 weight 访存、Q 与输出投影、attention kernel 和 batch。

**Q98：GQA 会使 QK attention 主计算量也减少 `H_q/H_kv` 倍吗？**  
A：通常不会。仍有 `H_q` 个不同 Q 头，各头需要计算自己的 attention scores 与加权 V；在 `H_q` 和 `d_h` 固定时，这部分主计算量仍约与 `H_q` 成正比。收益主要来自少算/少存 K/V 投影及更低 KV 访存。

**Q99：为什么 MQA/GQA 特别适合增量 decode？**  
A：每个新 token 都要反复读取历史 KV；压缩 KV 头数直接减少这部分高频访存。prefill 是较大的矩阵计算，可能没那么受 KV cache 读取限制，因此同一改动在 prefill 与 decode 上的收益并不相同。

**Q100：讲义第 58–61 页的算术强度推导想表达什么？**  
A：在 `T<d`、投影成本主导等简化前提下，prefill 能复用矩阵计算，算术强度较高；逐 token decode 每步读取权重和不断增长的 KV cache，算术强度低。MQA/GQA 降低 KV 项，使带宽瓶颈缓和。幻灯片的 `O(...)` 是抓主要项的数量级模型，**不是**可直接预测每个模型真实 latency 的精确公式。

**Q101：为什么只看 KV cache 大小不能断言 MQA 比 GQA 快多少？**  
A：整个 decode step 还包含所有层的参数读取、Q/O 投影、FFN、归一化、通信和 kernel 启动；如果这些占主导，KV 变小的速度收益会低于缓存缩减比例。还要考虑算子是否高效支持共享 KV。

**Q102：MQA 的质量代价来自哪里？**  
A：所有 Q 头共享同一组 K/V 表示，降低了 K/V 侧的头间多样性，可能损失表达能力。课件第 63 页展示的旧实验有轻微 PPL 上升；GQA 用多组 KV 在质量和效率之间提供连续的折中。具体差距要看模型和训练方式。

**Q103：GQA 论文中的 uptraining 是什么？**  
A：可以先把已训练 MHA checkpoint 的 K/V 头聚合成较少 KV 组，再继续训练，让模型适应该结构，而非从零重新训练。原论文报告了用少量额外预训练计算获得接近 MHA 的质量；这属于论文方案，不是所有 GQA 模型必须使用的训练流程。

**Q104：GQA 和 MLA 是同一个方法吗？**  
A：不是。GQA 的关键是多个 Q 头共享更少的 K/V 头；课件提到的 MLA 属于进一步压缩 KV 表示的不同方案（第 62 页仅点到为止）。面试若问 MLA 细节，应另外阅读对应模型论文，不能用“KV 头数变少”概括所有机制。

**Q105：启用 GQA 后，RoPE 对共享 K/V 有什么要求？**  
A：每个实际生成并缓存的 K 头需要按 token 的真实位置旋转；多个 Q 头可以读取同一个位置一致的 K 头。不能为每个 Q 头用不同位置或重复旋转已缓存 K，否则分数的相对位置关系会错。

**Q106：课件说‘GQA/MQA 减少 attention head cost’，如何避免误解？**  
A：把口径改成更精确的“减少 **KV 头数**，主要节省 KV 参数/cache/访存”；query 头数和每个 query 的 score 计算通常仍在。这样能解释为什么 GQA 对 decode 常很重要，却不保证 attention FLOPs 同比例下降。

## 9. 稀疏、滑动窗口与混合注意力（PDF 第 64–67 页）

课件最后强调：减少 KV 头数是一条轴，**限制每个 query 可见的 key 位置**是另一条轴。后者直接改变注意力模式，涉及更明显的长程信息取舍。

**Q107：全量 self-attention 为什么称为二次复杂度？**  
A：每个长度为 `T` 的序列中，约有 `T²` 对 query/key 位置需要计算分数；主导注意力乘法约 `O(BT²d)`。若显式保存每头分数矩阵，还会有 `O(BH_qT²)` 元素；高效 kernel 可降低中间存储，但不自动消除计算的二次项。

**Q108：因果 sliding-window attention 的规则是什么？**  
A：位置 `i` 通常只允许看自己及前面最多 `W−1` 个位置，即 `j∈[max(0,i−W+1),i]`。每个 query 最多访问 `W` 个 key，主导注意力计算变为约 `O(BTWd)`，当 `W≪T` 时显著低于全量注意力。

**Q109：窗口 attention 是否完全失去超过 `W` 的信息？**  
A：单层无法直接读取窗口外位置；但叠加多层后，中间 token 可以逐层传递信息，最远可影响的范围会扩大。若仅有局部层，传播路径可能长、质量也可能不如直接全局连接；“有间接路径”不等于“长距离检索同样容易”。

**Q110：为何把 full attention 与 sliding-window attention 交错？**  
A：局部层控制平均计算和缓存访问，全局层提供跨长距离的直接交互。课件第 65 页举 Command A：若干 RoPE+SWA 层后插入 NoPE+full 层；其他模型也有不同的局部/全局组合。参见 [Command A 相关原论文](https://openreview.net/pdf?id=Tp6ds3Dfqo)。

**Q111：如果每 4 层有 1 层 full attention，是否把整个模型的注意力复杂度降成线性？**  
A：没有。只要固定比例的层仍是 full，长序列下仍保留 `O(T²)` 项，只是二次项的系数比“每层 full”小。局部层增加 `O(TW)` 项；实际速度还要看 kernel、batch 和层间访存。

**Q112：NoPE 是什么意思？为什么可能与 full attention 搭配？**  
A：NoPE 指该注意力层不注入显式位置编码。课件中的 Command A 示例把它用于少量 full 层，而局部层使用 RoPE；这是某个模型的组合选择，不代表 full attention 一定应当不用位置编码。

**Q113：滑动窗口会怎样改变 KV cache 的保留策略？**  
A：若某层严格只关注最近 `W` 个 token，则更旧的 K/V 对该层未来解码可不再使用，理论上可只保留窗口范围；但混合架构中的 full 层仍可能需要完整历史 KV。实际可否逐层释放还受实现、prefix 复用和缓存管理影响。

**Q114：SWA、GQA 与 FlashAttention 解决的是同一个问题吗？**  
A：不是。SWA 减少允许的 query-key 配对；GQA 减少独立 K/V 头，重点节省 KV cache/访存；FlashAttention 一类算法通过分块/重算改进精确注意力的访存与中间存储。它们可以组合，但收益不应直接相乘。

**Q115：设计稀疏模式时最重要的质量风险是什么？**  
A：模型可能无法方便地取回窗口外的精确信息，或只能沿多层间接传递，导致长距离检索、跨段引用和长文一致性下降。应在真实目标任务和最大上下文长度上测质量，而不仅看困惑度与速度。

**Q116：对一个长上下文模型，怎样比较 full、SWA、混合 attention？**  
A：在相同参数、训练 token/算力和数据下，分别测 prefill 吞吐、decode 吞吐、KV cache 峰值、长距离检索与一般任务质量。要报告窗口大小和 full 层频率，因为“用了 SWA”这个标签本身不足以预测成本。

## 10. 综合面试题：把本讲的选择串起来

**Q117：给你一个 32 层、`d=4096`、SwiGLU `f=8d/3`、普通 MHA 的模型，怎样快速估算层参数？**  
A：先算每层注意力四个主要投影约 `4d²`，门控 FFN 三个矩阵约 `3d×8d/3=8d²`，共约 `12d²≈201M`；乘 32 层约 `6.44B`，再加 embedding/输出层等。这个算例假设 `H_qd_h=d` 且没有 GQA，实际模型要按配置调整。

**Q118：如果上题改为 GQA，哪个参数项先发生变化？**  
A：Q 与 O 仍按各自输出宽度核算，K/V 投影宽度改为 `H_kv d_h`，其参数由约 `d×d` 各自降为约 `d×H_kv d_h`；FFN 不因 GQA 改变。不能粗暴把整层 `12d²` 除以 `H_q/H_kv`。

**Q119：设计服务长 prompt、低 batch 解码的模型，优先考虑哪些权衡？**  
A：先区分 prefill 与 decode 瓶颈；考虑 GQA/MQA 降低 KV cache、局部/全局混合注意力降低长上下文成本，再评估 RoPE/位置方案的外推质量。最后用实际目标 batch、上下文长度与硬件测量，避免只按理论 FLOPs 决策。

**Q120：遇到训练 loss spike，你会怎样区分架构问题与数值问题？**  
A：先定位 spike 前首次异常的层、张量和值域，例如 Q/K norm、attention score、输出 logits、梯度和优化器状态；检查稳定 softmax 与混合精度。若数值实现正常，再用受控消融测试 QK-Norm、z-loss、soft-capping、学习率、Norm 位置等，而不是一次加入所有稳定技巧。

**Q121：面试官说‘RMSNorm 参数更少，所以一定能让大模型训练快很多’，如何回应？**  
A：指出相对主矩阵权重，Norm 参数占比通常很小；速度更多由数据搬运、kernel 融合和计算/带宽瓶颈决定。RMSNorm 在不少设置有收益，但应报告 wall-clock、吞吐和质量，而非只凭参数量下结论。

**Q122：面试官说‘MQA 把多头注意力变成单头注意力’，如何纠正？**  
A：MQA 仍保留多个不同的 **Q 头** 和各自的注意力权重；只把 K/V 头共享为一组。它不是把所有 query 合并为一个头。

**Q123：面试官说‘SWA 和 GQA 都减少注意力 FLOPs’，如何纠正？**  
A：SWA 通过减少可见位置，直接减少 `QKᵀ/AV` 的配对数量；GQA 主要减少 K/V 头和缓存访存，在 Q 头数及 head dim 不变时，attention-score 主计算不一定明显变少。

**Q124：如何从这节课提炼一个‘模型设计决策表’？**  
A：每提一个改动，至少填四格：它改变的**数学函数**、训练**稳定性/质量**、参数/FLOPs/显存或 KV 的**理论账本**、目标硬件上的**实测吞吐/延迟**。例如 SwiGLU 改函数和矩阵数量；GQA 改 KV 共享；SWA 改可见位置；z-loss 改训练目标。四格没填全，就还不能宣称某方案“更好”。

## 11. 常见混淆与讲义中的两处核对点

| 容易混淆的说法 | 更准确的说法 |
| --- | --- |
| “Pre-Norm 就是 RMSNorm” | Pre/Post 是**位置**；Layer/RMS 是**归一化算法**，可以交叉组合。 |
| “SwiGLU 比普通 FFN 少参数” | 若使用常见 `8d/3`，是为了与 `4d` 普通 FFN **近似匹配预算**。 |
| “RoPE 是在输入 embedding 上加一个向量” | 标准 RoPE 在 attention 的 Q/K 投影后做**位置相关旋转**。 |
| “GQA 使注意力头数变少” | 主要是 **KV 头数**减少；Q 头仍可保持不变。 |
| “只要每四层有一层 full，attention 就线性了” | 固定比例的 full 层仍保留 `O(T²)` 主项。 |
| “z-loss 等于稳定版 softmax” | 前者改变训练目标；后者是数值计算方法。 |

1. **第 43 页 PaLM 表格：**`48×258/18432≈0.672`，与打印的 `1.48` 不一致；原 PaLM 论文给出的 head size 为 `256`，按 `H d_h/d` 算为 `2/3`。请用原论文和实际配置核对，不背这行 ratio。
2. **第 54 页 z-loss 符号：**图中的写法按对数似然/最大化口径读；若按常见最小化交叉熵来写，应为 `CE + α(logsumexp(logits))²`。两个表达不能不说明目标方向就混用。

另有一个措辞提醒：第 61 页的 MQA “one dimension for keys and values” 从图和论文看应理解为“一组 KV 头”；单个 KV 向量仍有 `d_h` 个维度。
